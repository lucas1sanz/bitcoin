Level 2 Intermediate

Hardware Security

Hardware wallets are the single most impactful security upgrade for any Bitcoin holder. This level covers how they work, how they differ, and how to use them correctly.

What a Hardware Wallet Actually Does

A hardware wallet is a dedicated device whose sole purpose is to store private keys and sign transactions in a physically isolated environment. It is not a storage device for bitcoin — bitcoin lives on the blockchain. The hardware wallet stores the keys that prove ownership.

The Signing Flow

  1. Your computer (running Sparrow or another wallet app) builds an unsigned transaction (a PSBT — Partially Signed Bitcoin Transaction).
  2. The unsigned transaction is sent to the hardware wallet via USB or microSD card.
  3. The hardware wallet displays the transaction details on its own screen for you to verify (amount, destination address, fee).
  4. You physically confirm on the device (button press or touchscreen).
  5. The device signs the transaction internally — the private key never leaves the chip.
  6. The signed transaction goes back to your computer for broadcast.
ℹ️
What "secure element" means

A secure element (SE) is a tamper-resistant chip designed to resist physical attacks including power analysis, electromagnetic probing, and fault injection. It makes extracting keys via hardware attack significantly harder and more expensive. Not all hardware wallets have a SE — this is a meaningful security distinction.

Ledger — Security Analysis

Ledger produces the best-selling hardware wallets in the world. Their devices use genuine secure elements (ST33) which provide strong resistance to physical key extraction. However, several incidents have significantly damaged trust in the company.

Known Incidents

  • July 2020 — Customer data breach: Ledger's e-commerce database was breached, exposing the personal details of ~270,000 customers: full names, phone numbers, and physical home addresses. This data was published publicly on RaidForums. Multiple customers subsequently reported targeted physical threats and home burglaries.
  • December 2023 — Connect Kit supply-chain attack: Ledger's npm package @ledgerhq/connect-kit was compromised via a phishing attack on a former employee's npm account. The malicious version drained wallets connected to any dApp using the package. Estimated $600,000+ stolen in under two hours.
  • 2023 — Ledger Recover: Ledger announced a paid service that could send encrypted shards of your seed phrase to third parties for custody-based recovery. This revealed that the firmware architecture allowed the seed to be exfiltrated — undermining the core security claim. The service was later made opt-in.
⚠️
Closed firmware limits auditability

Ledger's secure element firmware is not open source. You cannot independently verify that the device does not exfiltrate your seed phrase via the USB connection. If you use Ledger, ensure you are on an air-gapped setup where possible, or accept this trust assumption.

Trezor — Security Analysis

Trezor, made by SatoshiLabs, was the first hardware wallet (2014). All firmware and hardware design files are fully open source — a significant trust advantage. However, the security posture varies significantly across models.

Model Differences

  • Model One / Model T: No secure element. Keys are stored in flash memory on a general-purpose microcontroller. Security researchers have demonstrated seed extraction via voltage glitching attacks. These attacks require lab equipment (~$200) and physical device access. The Kraken Security Labs attack (2020) extracted seeds in ~15 minutes from a Model One.
  • Safe 3 / Safe 5: Adds an Optiga Trust M secure element. Significantly raises the bar for physical attacks. Recommended if choosing Trezor.

Known Incidents

  • 2023 — Typosquatting attack: Attackers registered domains nearly identical to trezor.io (e.g., trézor.io with accented characters, trezőr.io) and served fake firmware update pages. Users who downloaded and installed the malicious firmware had their seeds extracted.
  • 2023 — Support database breach: ~66,000 users' contact details were exposed via a breach of a third-party support ticket platform used by Trezor.
ℹ️
Open source advantage

Trezor's fully open source design means researchers can and do audit the code. Security issues are found and disclosed publicly. This is healthier than security-through-obscurity. Coldcard and BitBox02 share this property.

Coldcard MK4 — Recommended Setup

The Coldcard MK4, made by Coinkite, is considered the gold standard for Bitcoin-only hardware wallets. It is fully open source, Bitcoin-only, air-gap capable, and features a thoughtfully designed security architecture.

Security Architecture

  • Dual-chip design: An ATECC608A secure element stores the encrypted seed; a separate STM32 microcontroller runs the firmware. Even if the firmware chip is compromised, it cannot access the raw seed without the SE's cooperation.
  • True air-gap: Can operate entirely via microSD cards — no USB connection required for signing. Supports NFC for PSBT transfer with NFC-capable companion apps.
  • Duress PIN: A secondary PIN that opens a plausible decoy wallet with a small balance. Tell an attacker this PIN and they see a functional wallet — your real wallet is protected.
  • Brick-me PIN: A third PIN that permanently destroys the device's secure element, making key extraction impossible even with lab equipment.
  • Bag tamper seal: Devices ship in a numbered, tamper-evident bag. Verify the bag number on the Coinkite website before setup.

First-Time Setup Protocol

  1. Verify bag tamper seal number at coinkite.com/bag-check
  2. Set a long PIN (prefix + suffix format: e.g., 1234-5678)
  3. Write down the two anti-phishing words displayed before you enter your PIN — verify them every login
  4. Generate a new seed on the device (do not import existing seeds onto a new device without wiping first)
  5. Write seed phrase, verify immediately
  6. Set up a passphrase (Level 3 — see level3.html)
  7. Export public key (XPUB) to Sparrow Wallet via microSD for watch-only wallet

BitBox02 — Setup & Security

The BitBox02 Bitcoin-only edition, made by Shift Crypto in Switzerland, is an excellent choice for users who want open-source hardware with a simpler interface than Coldcard.

Key Features

  • Fully open source — hardware, firmware, and companion app (BitBoxApp)
  • ATECC608A secure element — same chip used in Coldcard
  • microSD backup — the device creates an encrypted seed backup to microSD at setup; this file is protected by your device password
  • Bitcoin-only edition — reduced attack surface vs. the multi-edition
  • Simple UX — touch slider for confirmation; designed for non-technical users
ℹ️
No air-gap support

The BitBox02 requires a USB connection to the BitBoxApp for signing. This is a meaningful limitation compared to Coldcard. For users who want air-gap signing, use Coldcard (microSD) or SeedSigner (Level 4).

Verifying Receive Addresses on Device

This is one of the most important security habits for any hardware wallet user. Your computer screen is not a trusted display — malware can replace addresses shown in your wallet software. Your hardware wallet screen is the only trusted display.

Address Substitution Attacks

In an address substitution attack, malware running on your computer:

  1. Detects when your wallet software requests a receive address
  2. Silently replaces the displayed address with an attacker-controlled address
  3. You share this address with a sender — funds go to the attacker
🚨
Always verify on device

When Sparrow or any wallet app shows you a receive address, click "Verify on device" or "Show on device" — the hardware wallet will display the same address on its screen. If they match, the address is legitimate. This takes 5 seconds and prevents address substitution attacks entirely.

Protocol for High-Value Receives

  1. Generate address on device via wallet software
  2. Verify on hardware wallet screen
  3. Write down the first 8 and last 4 characters on paper
  4. Send to the sender via a separate communication channel (not copy-paste from the same machine)
  5. Ask the sender to read back the address to you

Firmware Update Protocol

Firmware updates patch security vulnerabilities but are also a vector for supply-chain attacks. Follow a careful protocol before updating.

Before You Update

  • Read the official release notes on the manufacturer's GitHub repository
  • Wait 48–72 hours after a new release to allow community review of the update
  • Verify the release signature using the manufacturer's published GPG key
  • Confirm you are downloading from the official domain only — bookmark it, do not google it
  • Check that your seed phrase backup is verified and accessible before updating
  • If possible, test the update on a secondary device first

After the Update

  • Verify that your wallet software still shows the correct expected addresses after the update
  • Confirm the first receive address on device matches your backup derivation
  • If anything looks wrong, do not use the updated device — restore from seed to a known-good device
