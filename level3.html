Level 3 Paranoid

Hardening

You have a hardware wallet and a verified backup. Now you go deeper: passphrase protection, metal backups, your own node, and privacy-preserving transactions.

BIP-39 Passphrase — The 25th Word

A BIP-39 passphrase is an optional extension to your 24-word seed phrase. It can be any string of characters — letters, numbers, symbols, any length. When combined with the seed words, it derives a completely different wallet with different addresses and different keys.

Key Properties

  • Any typo = empty wallet: If you mistype even one character of the passphrase, you get a valid but empty wallet. There is no "wrong passphrase" error — BIP-39 silently accepts any passphrase.
  • Plausible deniability: Keep a small balance in the wallet without passphrase (the "decoy wallet"). If coerced, reveal only the seed — the attacker sees a wallet with a small legitimate balance.
  • Separate storage is mandatory: The passphrase must never be stored with the seed words. Store the passphrase separately — in a different physical location, or memorized.
  • Adds another failure mode: If the passphrase is forgotten or lost, the bitcoin is gone. This is not a feature for everyone.
🚨
Test recovery BEFORE relying on it

Generate your wallet with passphrase. Write down the first receive address. Then on a fresh device (or after wiping), restore the seed words AND passphrase, and verify the first address matches exactly. A single character difference in the passphrase will silently produce a different empty wallet. Do this test before sending any meaningful bitcoin.

Recommendations

  • Use a passphrase of 12+ characters with mixed case and symbols
  • Avoid simple dictionary words or memorable phrases that an attacker might guess
  • Write the passphrase on a separate piece of metal backup (not paper)
  • Store passphrase backup in a completely different location from seed words
  • Consider keeping the passphrase memorized (with a written backup as failsafe)

Metal Seed Backups

Paper burns at 233°C. A typical house fire reaches 500–900°C. A laminated paper backup will not survive. Metal backups are the only reliable solution for long-term seed storage.

ℹ️
Titanium vs. Steel

Stainless steel melts at ~1370°C — right at the upper end of typical house fire temperatures (1200°C). In a prolonged or intense fire, steel backups can warp or melt. Titanium (Cryptotag Zeus) melts at 1668°C and is significantly more resistant. For multi-generational storage, titanium is worth the price premium.

Stamping Protocol

  1. Work in a secure, private location where others cannot observe
  2. Stamp one word at a time; verify each word on the BIP-39 word list before proceeding
  3. For abbreviation-based systems: use the official 4-letter BIP-39 abbreviations
  4. Store in a waterproof container (e.g., vacuum-sealed bag) inside a TL-rated safe
  5. Never photograph the completed backup
  6. Test that the words are legible and match your seed before destroying paper backup

Running Your Own Node

When you use someone else's node, you trust them to tell you the truth about the blockchain. They can lie about your balance, hide incoming transactions, or correlate your addresses with your IP address. Running a full node means you validate every transaction yourself.

Recommended Hardware

  • Raspberry Pi 4 (4GB+ RAM) — ~$55 for the board
  • 2TB+ SSD (not HDD — too slow for IBD) — ~$90–$150. The blockchain is ~650GB as of 2025, growing ~70GB/year.
  • Case with active cooling — the Pi4 runs hot during IBD
  • 16GB+ microSD for the OS (the SSD will hold the blockchain)

Software Options

  • Bitcoin Core — the reference implementation. Bare-metal, maximum control. Recommended for advanced users.
  • Umbrel — Docker-based node-in-a-box with a web UI. Easiest setup. Also runs LND for Lightning.
  • myNode — Similar to Umbrel, with a paid tier for additional features.
  • RaspiBlitz — Terminal-based, highly configurable, excellent for learning.

Electrum Server (for Sparrow)

Sparrow Wallet can connect to your node via an Electrum protocol server. Two implementations:

  • Fulcrum — Faster, optimized for SSD. Recommended for Sparrow users. Takes ~2-3 days to sync after Bitcoin Core is synced.
  • Electrs — Lower RAM usage. Good for 4GB Pi.
ℹ️
Initial Block Download (IBD) takes time

Syncing Bitcoin Core from scratch takes 1–4 days on a modern internet connection with an SSD. Do not be alarmed by slow block sync in the early stages — it speeds up significantly as you approach the tip. Do not interrupt the process.

Sparrow Wallet as Control Plane

Sparrow Wallet is a desktop Bitcoin wallet for serious users. It is fully open source, Bitcoin-only, and provides granular control over every aspect of transaction construction. It is the recommended companion to Coldcard for watch-only management and PSBT signing.

Key Features

  • PSBT support: Import unsigned transactions from Coldcard via microSD, sign on device, return signed PSBT for broadcast
  • Watch-only wallet: Import your hardware wallet's xpub — Sparrow tracks all addresses and balances without keys on the computer
  • Coin control: Manually select which UTXOs to spend in each transaction
  • UTXO labeling: Tag each UTXO with source information at receive time
  • Own node connection: Connect to your Bitcoin Core node or Electrum server
  • Multisig: Full multisig wallet creation and management
  • Transaction graph: Visualize the inputs and outputs of any transaction

Connecting to Your Own Node

  1. Open Sparrow → Preferences → Server
  2. Select "Private Electrum" (for Fulcrum/Electrs) or "Bitcoin Core" (for direct RPC)
  3. Enter your node's local IP address and port
  4. Test connection — Sparrow will show a green indicator and current block height
  5. Create or import your hardware wallet watch-only wallet

Coin Control and UTXO Management

Bitcoin is a UTXO (Unspent Transaction Output) model. Every bitcoin you receive is a specific output, identified by its transaction hash and output index. When you spend, you consume one or more UTXOs as inputs and create new outputs.

Why Coin Control Matters for Privacy

Combining UTXOs from different sources in a single transaction links them on the blockchain. A blockchain analysis firm can infer that the same person controlled all inputs in a transaction. This is called the Common Input Ownership Heuristic.

Example: You receive 0.1 BTC from a KYC exchange (your identity is known) and 0.05 BTC from a peer (anonymous). If you combine them in one transaction to pay someone, the blockchain analyst can link your peer-received UTXO to your known identity.

UTXO Labeling Protocol

In Sparrow Wallet, label every UTXO when you receive it with:

  • Source: Where the bitcoin came from (e.g., "Coinbase withdrawal", "Peer payment from Alice", "Mining reward")
  • Date: When received
  • Privacy context: Whether the source is KYC (linked to your identity) or private
⚠️
Change outputs reveal wallet structure

When you send bitcoin and receive change back, the change output is linked to your wallet. Consider sending exact amounts when possible, or use a PayJoin transaction to obscure the change. Never reuse addresses — each UTXO should go to a fresh address.

Tor and Network Privacy

Without Tor, every node you connect to sees your IP address. Internet service providers and blockchain surveillance companies can correlate IP addresses with transaction broadcasts to identify wallet owners.

Configuring Bitcoin Core with Tor

Edit your bitcoin.conf file (location: ~/.bitcoin/bitcoin.conf on Linux/Mac):

# Route all connections through Tor
proxy=127.0.0.1:9050
onlynet=onion

# Optional: advertise your own .onion address (requires Tor hidden service)
# listen=1
# bind=127.0.0.1

Run the Tor daemon on the same machine (install via your OS package manager). Bitcoin Core will connect to peers via Tor, hiding your IP address.

Sparrow Wallet Tor Settings

Sparrow has a built-in Tor client:

  1. Open Sparrow → Preferences → Server
  2. Enable "Use Tor"
  3. Sparrow will route its server connection through Tor
ℹ️
Tor slows things down

Tor connections are slower than clearnet. Expect initial block downloads and wallet syncs to take longer. For daily use, the privacy benefits outweigh the speed cost. You can disable Tor for large IBDs and re-enable for normal use.

Transaction Broadcast Privacy

Even with Tor, the node that first sees your transaction can infer it originated from you. Mitigations:

  • Broadcast via your own node (so only your node initiates — but your node's .onion address could still be traced over time)
  • Use Sparrow's built-in Tor broadcast to broadcast through the Tor network
  • For maximum privacy: broadcast from a Tor-only node running on a separate machine
